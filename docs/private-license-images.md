# 免許証画像の非公開化

## 実装

- アップロードは検証済みCognito IDトークンを必須とする。キーは `LicenseUploads/<Cognito sub>/<random ID>-<file>`。JPEG/PNG/WebPのマジックバイトと7MB上限を確認（完全な画像デコード・マルウェア検査ではない）。
- 登録保存APIもCognito認証を必須とし、他人のキープレフィックスや任意の外部URLを拒否。DBには `license_image_key` / `license_image_key_2` を保存する。URLフィールドは削除する。
- 表示用には認証が必要な `/api/license-image` を返す。APIで本人または管理者を確認後、S3の公開アクセスブロックとContent-Typeを確認し、有効期間60秒の署名付きGETへ302リダイレクトする。署名URLは取得者が共有すると期限まで使える。DB・ログに保存しない。
- 管理者は既存画面のBasic認証をAPIでも検証する。ただし `ADMIN_BASIC_USER` / `ADMIN_BASIC_PASS` の明示設定が必要で、ソース内の既定値は認めない。HTTPS必須。中長期的には管理者用IdP/ロールへ移行する。
- レスポンスと署名付きGETに `private, no-store`、リダイレクトに `Referrer-Policy: no-referrer` を指定。すでに第三者が保存した画像やキャッシュを取り消すことはできない。
- 旧URLは同じバケット、または `LICENSE_UPLOADS_LEGACY_BUCKET` に明示した移行元バケットの免許証プレフィックスに限定して読み替える。画像の取得・署名は常に移行先の非公開バケットで行い、移行元へフォールバックしない。既存ユーザーが登録内容を再保存した場合もキーへ変換する。

## 本番への適用（AWS設定はコード変更だけでは変わらない）

1. 本番のコミット、実際の `LICENSE_UPLOADS_BUCKET`（なければ `PHOTO_UPLOADS_BUCKET`、さらに未設定なら `yasukari-file`）、`LICENSE_UPLOADS_PREFIX`（既定 `LicenseUploads/`）を特定する。値に秘密情報を混ぜない。
2. DynamoDBのバックアップ/PITRと、S3の既存オブジェクトの保全を確認する。過去の匿名アクセス調査に必要なログも保全する。
3. バケットが公開サイト画像等と共用か確認する。**共用バケットへ公開アクセスブロックを無条件に適用しない。** 共用の場合は非公開の専用バケットに免許証を同じキーでコピーし、`LICENSE_UPLOADS_BUCKET` を専用バケット、`LICENSE_UPLOADS_LEGACY_BUCKET` をコピー元バケットに設定する。本スクリプトはバケット間コピーをしないため、同じキーでコピーを完了してからDBのキー移行を行う。コピー元の免許証も匿名取得できないようプレフィックスのポリシー/ACL・CDNを確認し、古いコピーを残したまま完了としない。
4. 対象バケットのBlock Public Accessを4項目すべて有効にする。既存画像にも適用される。ポリシー・ACL・アクセスポイント・CloudFront経由で不要な第三者が読めないことも確認する。このアプリは4項目の有効化を取得できなければアップロードと画像取得を拒否する。
5. アプリのIAMロールに対象バケットの `s3:GetBucketPublicAccessBlock`、免許証プレフィックスの `s3:GetObject` / `s3:PutObject` を付与する。SSE-KMS利用時は対応するKMS権限も必要。DynamoDBは従来のユーザーテーブルへの権限が必要。管理者Basic認証情報とCognito設定も確認する。
6. 修正版を配置し、非公開化と切り替えを調整する（切り替え中は旧画像表示が一時停止する可能性がある）。下記で旧DB URLをキーへ移行する。別バケットへコピーした場合は `LICENSE_UPLOADS_LEGACY_BUCKET` も明示する。既定は読み取り専用。`--apply` は実データを更新するため、対象とバックアップを確認後に実行する。

```bash
# 対象バケット名・テーブル名を実際の設定に置き換えて実行する
LICENSE_UPLOADS_BUCKET=YOUR_PRIVATE_BUCKET USER_TABLE=YOUR_USER_TABLE \
AWS_REGION=ap-northeast-1 node scripts/migrate-license-images.cjs

# 検証成功後、同じ環境変数を指定して --apply を追加する
```

スクリプトはページングし、S3オブジェクトの存在を検証して、旧値が変化していないことを条件に更新する。ログにユーザー情報やURLは出さない。途中失敗時は一部更新済みの場合があるが再実行可能。未知のURL・バケット・競合は拒否する。公開設定は変更しない。

## 本番検証

- 未ログインで管理一覧・画像取得・アップロード・登録保存が拒否される。
- 一般ユーザーが他人のuserId、他人のkeyを指定しても拒否される。
- 本人と設定済み管理者は既存画像と新規画像を表示できる。日本語/英語の登録で保存と再表示を確認する。
- S3の旧通常URLを認証なしで取得しても画像本文が返らない。CloudFront等の別経路も検証する。
- 署名付きURLは期限経過後に拒否され、通常の画像応答にキャッシュ禁止が付く。
- アップロード後、DBに新しいS3公開URLが保存されない。

署名URLだけを導入しても、公開済みオブジェクトは非公開にならない。AWS設定・既存データの移行・本番検証が終わるまで非公開化完了と扱わない。

## 開発環境の検証結果

セキュリティ・互換性・関連テストとTypeScript検査、本番ビルドを確認。S3クライアントと署名SDKは同一バージョンに固定し、実際のSDK同士で署名URLを生成するテストも追加した。React 18用の型定義を明示し、ビルド時の自動インストールを防止。AWS実接続・ブラウザでの本番動作・移行の適用は未実施。

依存関係にS3署名URL用SDKを追加。既存ロックファイルは宣言済みのAWS SDK・テスト依存等も不足していたため、整合するロックを再生成した。解決されたAWS SDKはNode.js 20以上を要求するので、配置前に本番のNode.jsバージョンを確認する。Next.js自体の更新はこの変更には含めていない。

移行時は旧アプリからの書き込みとの競合に注意する。最初のコピー後に環境変数を設定・ビルドしてアプリを切り替え、旧アプリの書き込みが止まってから差分コピーを再実行する。その後にDB移行のdry-run、バックアップ確認、適用を行う。コピー元の画像は削除せず、外部読み取り拒否を維持する。移行先のIAMにはアプリロールのGetObject/PutObject/GetBucketPublicAccessBlockを用意する。PM2の保存済み環境変数が.envを上書きしていないことも確認する。
